# Чеклист захисту курсової та технічної співбесіди: WarehouseReserveSystem

> **Призначення:** Шпаргалка для впевненого захисту проєкту перед комісією університету або технічним лідом/рекрутером. Пояснення кожної архітектурної деталі людською мовою без затинань.

---

## 🎯 1. Що це за система одним реченням
**WarehouseReserveSystem** — це повнофункціональна корпоративна система адресного складського обліку (WMS) на .NET 8 / C# з підтримкою транзакційного переміщення товарів, контролю дефіциту залишків, генерації первинних документів (PDF-накладні) та аудиторського сліду.

💡 *Як сказати це одним словом наступного разу:* **WMS (Warehouse Management System)**.

## 🎬 3. Сценарій живої демонстрації (5–7 хвилин)

### Крок 1: Головний дашборд (45 секунд)
1. Відкриваємо `http://localhost:5000` (або `http://localhost:8090` у Docker / `http://152.70.19.219:8090` на VPS).
2. Демонструємо аналітичні KPI-картки у темній темі:
   - **Загальна вартість залишків на складі** (сума собівартості всіх товарів на залишку).
   - **Активні позиції (SKU)**.
   - **Кількість складів та адресних зон**.
   - **Критичні сповіщення дефіциту** (товари, залишок яких менший за MinStockThreshold).
3. Показуємо віджет останніх складських операцій.

### Крок 2: Адресна сітка складу (1 хвилина)
1. Переходимо у розділ **«Склади та зони»** (`/Warehouses`).
2. Показуємо ієрархію: **Склад** $\rightarrow$ **Зона** (наприклад, Зона палетного зберігання) $\rightarrow$ **Комірка** (`A-01-02-B` = Ряд 1, Стелаж 1, Полиця 2, Комірка B).
3. Відкриваємо деталі конкретного складу: видно зайнятість комірок і конкретні товари, що лежать у кожній фізичній комірці з номерами партій.

### Крок 3: Складські рухи та захист від оверселінгу (2 хвилини)
1. Переходимо у **«Рух товарів»** (`/Movements`).
2. **Прихід товару (Receipt):** Оформлюємо надходження товару від постачальника у вибрану комірку з вказанням партії. Залишок миттєво зростає.
3. **Захист від від'ємного залишку (Shipment):** Пробуємо відвантажити 999 одиниць товару, коли на складі є лише 15.
   - *Ефект:* Система блокує операцію з чіткою людською помилкою: *"Недостатньо залишку товару в комірці (запитано 999, є 15)"*. Від'ємного залишку бути не може!
4. **Атомарне переміщення (Transfer):** Переміщуємо 5 одиниць з комірки `A-01-01-A` в `A-01-02-B`. Показуємо, що операція відбувається всередині єдиної транзакції бази даних: в одному місці списано, в іншому нараховано.

### Крок 4: PDF-документи та експорт (1 хвилина)
1. Відкриваємо будь-який проведений документ руху.
2. Тиснемо кнопку **«Завантажити накладну (PDF)»**.
3. Відкривається офіційна складська накладна формату А4 з номерами, переліком артикулів, кількістю, ціною, загальною сумою та полями підписів («Здав/Прийняв»).
4. Переходимо в **«Аналітика та звіти»** (`/Reports`) і завантажуємо актуальний CSV-баланс для бухгалтерії.

### Крок 5: Аудиторський журнал (Security & Compliance) (45 секунд)
1. Заходимо під аудитором або адміном у **«Журнал аудиту»** (`/AuditLogs`).
2. Показуємо повний слід дій: хто, коли (UTC), з якої IP-адреси, яку дію виконав (`StockReceipt`, `StockShipment`, `StockTransfer`, `CreateProduct`). Записи аудиту незмінні (Append-Only).

## 🛡️ 4. Питання-пастки та забійні відповіді

### Q1: Чому комірка розбита на Ряд, Стелаж, Полицю і Комірку, а не просто вільний рядок тексту?
> **Відповідь:** Адресне зберігання (Aisle-Rack-Shelf-Bin) — це основа сучасної логістики. Це дозволяє в майбутньому алгоритмічно будувати оптимальний маршрут комірника при складанні замовлення (TSP / хвильове комплектування), автоматично фільтрувати комірки за ваговими та об'ємними обмеженнями і виключати людський фактор пошуку товару «на око».

### Q2: Що станеться, якщо двоє комірників одночасно спробують відвантажити останню одиницю товару? (Race Condition)
> **Відповідь:** У нашому `InventoryService` операції списання та переміщення виконуються у явно відкритій транзакції `await _context.Database.BeginTransactionAsync()`. Зчитування поточного залишку та його модифікація захищені транзакційною ізоляцією. Якщо другий комірник спробує зняти одиницю після того, як перший вже зафіксував списання, перевірка залишку викине виключення `InvalidOperationException`, транзакція другого комірника відкотиться (`Rollback`), і залишок ніколи не впаде нижче нуля.

### Q3: Чому ви не видаляєте товари через звичайний `context.Products.Remove(product)`?
> **Відповідь:** У нас реалізовано патерн **Soft Delete** (`IsActive = false`). Якщо товар мав хоча б один рух або за ним числиться історія в накладних, фізичне видалення призвело б або до `Foreign Key Violation`, або до втрати фінансової звітності підприємства. Якщо залишків немає — система може видалити запис, але якщо залишки чи історія є — товар деактивується і приховується з нових операцій, зберігаючи цілісність історії.

### Q4: Як забезпечено швидкість пошуку при сотнях тисяч позицій?
> **Відповідь:** У `ApplicationDbContext` ми явно створили індекси:
> 1. Унікальний індекс на `Product.Sku` (пошук за артикулом $O(1)$).
> 2. Індекс на `Product.Barcode` (миттєвий пошук сканером штрих-кодів).
> 3. Складений індекс `(ProductId, StorageLocationId)` на таблиці `StockItems` для миттєвої перевірки залишку в конкретній комірці без сканування всієї таблиці (Index Scan замість Full Table Scan).

### Q5: Які ролі користувачів є в системі і чим вони відрізняються?
> **Відповідь:**
> - `Admin`: повний доступ (керування довідниками, складами, товарами, користувачами, аудит).
> - `Storekeeper` (Комірник): операційний доступ (прийомка, відвантаження, внутрішнє переміщення, друк накладних).
> - `Auditor` (Аудитор/Бухгалтер): режим перегляду звітності, аналітики, залишків та читання журналу аудиту без права зміни фізичних залишків.

## 🔑 5. Тестові ролі та безпечний доступ

Для демонстрації у системі реалізовано **Швидкий демо-вхід (1 клік)**, що дозволяє миттєво перемикати ролі без ручного вводу чи розкриття паролів на екрані:

- 🛡️ **Адміністратор (`Admin`)**: Керування товарами, складами, персоналом, повний аудит.
- 📦 **Старший комірник (`Storekeeper`)**: Прийомка, відвантаження, внутрішнє переміщення, друк PDF-накладних.
- 📋 **Фінансовий аудитор (`Auditor`)**: Режим перегляду, звітність, аналітика, експорт CSV-залишків, перегляд аудиту.

## 🚀 6. Швидкий запуск

### Варіант А: Локально (через .NET CLI)
```bash
# 1. Перейти в корінь проєкту
cd C:\Project\WarehouseReserveSystem\WarehouseReserveSystem

# 2. Запустити застосунок (БД створиться і наповниться автоматично)
dotnet run

# 3. Відкрити у браузері
# http://localhost:5000
```

### Варіант Б: Запуск тестів
```bash
cd C:\Project\WarehouseReserveSystem
dotnet test
```

### Варіант В: У Docker Compose (App + PostgreSQL)
```bash
cd C:\Project\WarehouseReserveSystem
docker-compose up --build
```
Додаток доступний на `http://localhost:8090` (або `http://152.70.19.219:8090`).
